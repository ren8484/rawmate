# RAWMate 1.4 去留模型

## 状态

每张 JPG 作为决定入口，最终状态互斥：

| 状态 | 用户含义 | 执行清理 |
|---|---|---|
| 未决定 | 尚未选择 | 不处理 |
| P | 保留 JPG + RAW | 不处理 |
| J | 仅保留 JPG | 回收同名 RAW |
| R | 仅保留 RAW | 回收 JPG |
| X | JPG + RAW 都不要 | 先回收 RAW，再回收 JPG |

P/X 是常用动作，J/R 是例外动作，但四者都支持键盘；右键菜单只显示“标记为废片 / 保留双格式 / 保留 JPG / 保留 RAW”，不附快捷键字母，也不提供打开原图或立即删除照片的菜单项。

## 统计与导航

- 已决定：P + J + R + X。
- 保留：P + J + R；废片：X。
- 完成弹框额外列出双格式、仅 JPG、仅 RAW。
- “挑片”前后导航跳过所有已决定状态；“浏览”按当前排序逐张移动。
- 标记只保存决定，不移动文件。

## 清理事务边界

1. 只从当前 `root\jpg` 正向枚举 J/R/X，配对也只查当前 `root\arw`。
2. 生成计划时拒绝链接目录/文件、重复 stem 与 R 缺少 RAW。
3. 用户看到当前目录、J/R/X 分项及 JPG/RAW 总数后确认。
4. 执行每组前再次校验当前决定、绝对目录边界、唯一配对、文件大小与最后写入时间。
5. R 先原子保存 RAW 保留记录，再回收 JPG；X 先回收 RAW，失败时保留 JPG 和 X 供重试。
6. 只按精确成功路径收尾；失败项保留决定。每组后原子保存，重复执行不会再次处理已完成项。

所有文件移动都进入 Windows 回收站，不永久删除。

## 持久化

`cull-marks-v2.txt` 第一行为 `RAWMate-CullMarks|2`。P/J/R/X 记录 JPG 的 Base64 绝对路径；内部 K 记录完成 R 清理后仍存在的 RAW。保存使用临时文件和替换，并保留 `.bak`。读取损坏时阻止后续保存与清理。

测试版的设置和决定与正式版隔离；缩略图及 EXIF 拍摄时间属于可丢弃派生缓存，可以共享。持久缩略图键包含规范化绝对路径、文件大小和最后写入时间，源照片变化时自动失效。

## 清理后刷新

清理完成只淘汰成功移除 JPG 的内存缓存，不清空整批缩略图。若当前 JPG 被成功回收，按清理前当前排序选择其后的第一张仍存在照片并在末尾回绕；若当前 JPG 未被成功回收，则保持当前照片。
